이번에 테크택에서 확인할 질문은 명확하다. “Terra가 싸다는데, Sol을 계속 쓸 이유가 있나?” 사용자가 이 비교를 요청했고, AI 에이전트에게 공식 문서 대조와 비용 계산을 맡겨 확인했다. 모델 이름만 보고 등급표를 만들기보다, 실제로 맡길 업무와 마지막 영수증을 같이 보는 방식이다.

벨로키의 동전 1개와 2개는 동일 조건의 토큰 단가를 표현한다. 성능이 두 배라는 뜻은 아니다. 점눈은 작아도 영수증은 꼼꼼히 본다.

공식 문서가 나누는 Terra와 Sol의 역할

OpenAI는 Terra를 시각 추론, 정밀한 컴퓨터 조작, 명료하고 자연스러운 글쓰기에 맞는 빠르고 효율적인 모델로 소개한다. 모델 선택 문서에서는 제공된 자료를 바탕으로 한 간결한 글쓰기, 목표가 정해진 화면 작업, 범위가 좁은 코드 수정도 후보로 든다. 따라서 Terra를 “코딩은 못 하는 글쓰기 전용 모델”로 이해하면 범위를 지나치게 좁힌 셈이다. Terra 공식 설명, 모델 선택 기준

Sol은 복잡한 코딩, 컴퓨터 사용, 전문 업무를 위한 모델이다. Work·Codex 문서는 코드·앱·문서를 오가며 반복하거나 오래 수행하는 작업에도 Sol을 제안한다. 여기서 OpenAI가 말하는 “Astra에 가까운 성능을 더 낮은 비용으로”의 비교 대상은 Astra다. Terra와 품질이 같다는 설명으로 읽으면 안 된다. Sol 공식 설명, Work·Codex 모델 문서

예를 들어 이미 검증한 제품 설명을 블로그 문장으로 다듬는 일은 Terra의 출발점에 가깝다. 반면 서로 충돌하는 요구사항을 정리하고, 여러 파일을 고치고, 테스트 실패 원인까지 따라가는 일은 Sol부터 검토할 만하다. 둘 다 컴퓨터를 쓴다고 업무 난도가 같은 건 아니다. 엑셀 켜는 사람 모두가 결산 담당자는 아니니까.

컨텍스트 윈도는 모델이 한 번에 다룰 수 있는 정보의 공간이다. 책상 크기라고 생각하면 쉽다. 두 모델 모두 105만 토큰의 책상을 제공하며, 모델 페이지의 최대 입력은 92만 2천 토큰, 최대 출력은 12만 8천 토큰이다. Terra가 저렴한 이유를 “책상이 작아서”라고 설명할 근거는 없다. Terra 사양, Sol 사양

추론 강도는 생각에 들일 작업량을 조절하는 설정이다. Terra는 none도 지원하지만 Sol은 지원하지 않으며, API 문서는 둘 다 기본값을 medium으로 제시한다. 실제 앱의 선택지와 기본값은 계정·클라이언트에 따라 다를 수 있다. 처음 비교할 때는 공통으로 지원하는 medium과 같은 입력을 쓰는 편이 조건을 맞추기 쉽다. GPT-6 문서, Work·Codex 설정 설명

API 토큰 가격: 같은 양이면 정확히 반값이다

다음은 2026년 10월 28일 확인한 Standard 속도·입력 272K 이하 구간의 API 가격이다. 단위는 100만 토큰당 미국 달러이며, 구독료나 Codex 크레딧이 아니다. 캐시 입력은 이전에 저장된 공통 입력을 재사용할 때의 읽기 요금이다. 공식 API 가격표

동일 조건의 각 항목에서 Terra가 50% 저렴하다. 하지만 단가가 절반이라는 사실만으로 같은 작업의 총비용까지 절반이라고 정할 수는 없다. 두 모델이 생성하는 출력량, 추론량, 재시도 횟수가 달라질 수 있기 때문이다. 가격표는 단위를 알려주고, 사용 기록은 수량을 알려준다. 영수증에서 수량 칸을 접어두면 할인율만 남는다.

또 하나, 화면에 보이는 답변 길이가 청구 출력의 전부는 아니다. 추론 토큰도 컨텍스트를 차지하며 출력 토큰 요금으로 과금된다. 아래 계산의 “출력 5천 토큰”은 보이는 본문과 청구 대상 추론을 합친 가정값이다. 한국어 글자 수를 토큰 수로 그대로 바꿔 넣지 말고, 실제 사용량을 확인해야 한다. 추론 토큰 과금 설명

입력 2만·출력 5천 토큰을 계산해보면

비교를 위해 일반 입력 20,000토큰과 청구 출력 5,000토큰을 쓰는 가상 작업을 잡았다. 실제 모델을 실행한 성능 측정이 아니라, 공식 단가를 넣어 Python으로 재현한 산술 예제다. 캐시·도구 호출·지역 할증·세금은 이 첫 계산에서 제외했다.

Terra = 20,000 / 1,000,000 × $1
      +  5,000 / 1,000,000 × $5  = $0.045

Sol   = 20,000 / 1,000,000 × $2
      +  5,000 / 1,000,000 × $10 = $0.090

같은 작업을 같은 물량으로 1,000번 처리한다면 Terra는 $45, Sol은 $90다. 이것이 “동일 토큰이면 반값”의 정확한 뜻이다. 다만 1,000건이 모두 같은 품질로 끝났다는 실험 결과는 없다. 계산기는 곱셈을 잘하지만 결과물 검수까지 대신해주진 않는다.

캐시와 장문 구간도 나눠 계산했다. 아래 캐시 예제는 이미 캐시가 만들어져 적중한 요청의 읽기 비용이며, 캐시 생성·유지에 필요한 쓰기 비용은 제외했다. 장문 예제는 입력이 272K를 넘으면 전체 요청에 입력·캐시 2배, 출력 1.5배 단가가 적용된다는 규칙을 반영했다. 캐시·장문 요금

가상 요청 조건 Terra Sol
일반 입력 20,000 + 출력 5,000 $0.045 $0.090
새 입력 2,000 + 캐시 읽기 18,000 + 출력 5,000 $0.0279 $0.0558
일반 입력 300,000 + 출력 5,000, 장문 단가 적용 $0.6375 $1.275

105만 토큰까지 담을 수 있다는 사양과, 272K를 넘길 때 가격 구간이 바뀐다는 규칙은 별개다. 예를 들어 저장소 자료를 30만 토큰씩 넣는다면 짧은 요청의 단가를 그대로 곱하면 안 된다. 책상이 크다고 서류를 전부 펼칠 필요는 없다. 필요한 파일부터 좁히는 습관은 모델 선택과 별도로 유효하다.

Codex 크레딧은 달러 가격표와 분리해서 읽자

ChatGPT로 로그인해 Codex·Work를 쓰는 독자라면 크레딧 표를 따로 봐야 한다. 공식 Standard 요율은 다음과 같으며, 100만 토큰당 크레딧 단위다. Codex 크레딧 청구에는 별도 캐시 쓰기 요금이 없고, API 키로 사용하면 API 가격 체계를 따른다. Codex·Work 가격 문서

같은 가상 물량인 입력 20,000·출력 5,000이면 Terra는 1.125크레딧, Sol은 2.25크레딧이다. 크레딧 표에서도 동일 토큰 기준 비율은 같다. 다만 이 수치를 “내 구독에서 정확히 두 배 많은 작업을 할 수 있다”로 바꾸면 안 된다. 포함 사용량은 모델·업무·추론·도구·캐시 등의 영향을 받고, 현재 한도는 계정의 사용량 화면으로 확인해야 한다. 사용량과 요금 구분

따라서 달러 예제와 크레딧 예제는 서로 다른 계기판이다. API 예산을 잡을 때는 API 청구 기록을, 구독으로 일할 때는 실제 남은 한도와 사용 기록을 보자. 계기판 두 개를 더해서 주행거리를 계산하면 차도 당황한다.

Terra로 시작했다가 Sol에 다시 맡기면 언제 손해일까

첫 예제에서 Terra 한 번은 $0.045, Sol 한 번은 $0.09였다. 이제 Terra로 먼저 처리한 작업 중 비율 p를 Sol에 한 번 더 맡긴다고 가정하자. 재처리 때도 입력·출력 물량이 같고 Sol은 한 번에 끝낸다는 단순 모형이다. 평균 토큰 비용은 $0.045 + p × $0.09가 된다.

Terra 처리 후 Sol 재처리 비율 작업당 평균 비용 처음부터 Sol $0.09 대비
0% $0.045 50% 절약
20% $0.063 30% 절약

이 가정에서는 절반을 Sol에 다시 맡기는 순간 토큰 비용 절약이 사라진다. 실제로는 실패한 대화와 도구 로그까지 재전송할 수 있어 재처리 물량이 더 커질 수도, 일부만 보내 더 작아질 수도 있다. 따라서 50%는 모든 업무에 통하는 실측 기준이 아니라, 단가만 보던 판단을 재처리까지 넓혀주는 계산 기준이다.

사람의 검수·수정 시간까지 넣으면 선택은 더 달라진다. 같은 계산에서 $0.045를 아꼈어도 사람이 오류를 찾느라 오래 붙잡혀 있다면, 그 작업의 절약을 별도로 평가해야 한다. 제가 팀을 운영한다면 모든 일을 싼 모델로 시작하도록 강제하기보다, 승인 가능한 결과가 안정적으로 나오는 경계를 먼저 정하겠다. AI 요금은 줄었는데 사람이 야근하면 비용이 퇴근한 게 아니라 부서를 옮긴 셈이다.

그래서 어떤 모델을 기본값으로 둘까

테크택의 선택은 업무를 나누는 쪽이다. 제공한 자료의 재작성·이미지와 화면 해석·범위가 작은 수정은 Terra를 먼저 검토하고, 여러 파일·도구·상충하는 근거를 오래 조율할 일은 Sol부터 검토하자. 공식 용도를 바탕으로 한 운영 제안이며, 아래 예시는 우열을 측정한 벤치마크가 아니다. 공식 업무별 선택 기준

독자가 맡길 일 먼저 비교할 출발점 바꿔야 할 신호
검증된 메모를 블로그 초안으로 다듬기 Terra 사실 누락·독자와 어조 불일치가 반복됨
대시보드 캡처의 수치·라벨 해석 Terra 불확실한 숫자를 단정하거나 원본과 어긋남
범위와 테스트가 정해진 작은 코드 수정 Terra 수정 범위를 벗어나거나 회귀 테스트에 실패함
여러 파일을 고치며 원인 추적하기 Sol 간단한 반복 작업이라 비용을 낮출 여지가 있음
충돌하는 자료로 실행 계획 만들기 Sol 요구사항이 단순해져 Terra로도 기준을 충족함

모델 하나만 골라야 한다면 주업무가 기준이다. 글과 시각 자료를 자주 다루면 Terra부터, 복잡한 개발·설계·통합 작업이 많으면 Sol부터 시작하자. 어느 쪽이든 실제 대표 작업에서 검수 기준을 못 넘으면 선택을 바꿔야 한다. “가장 싼 모델”보다 “고칠 일이 적은 완료물”을 고르는 게 이 비교의 목적이다.

검증할 때는 같은 자료·같은 요구사항·공통 추론 강도 medium으로 두 결과를 비교하자. 미리 정한 필수 사실·문체·테스트 통과 여부와 함께 입력/캐시/청구 출력 토큰, 도구 호출, 재시도, 완료시간, 사람의 수정시간을 기록한다. 작은 표 하나면 충분하다. 모델 응원전보다 다음 달 영수증에 훨씬 도움이 된다. 공식 비교 방법

어디까지 확인한 비교인가

이번 글은 2026년 10월 28일 공식 문서 대조와 AI 에이전트의 Python 비용 계산에 근거한다. 사용자가 두 모델을 직접 장기간 사용했다거나, 같은 과제를 실행해 Terra의 실제 토큰 소비가 절반이었다는 경험은 주장하지 않는다. 정답률·지연시간·한국어 문체의 승자는 아직 측정하지 않았다.

확인하면서 달라진 판단은 분명하다. Terra를 한도 작은 저가 모델로 보는 대신, 같은 토큰 공간에서 다른 업무와 단가를 가진 선택지로 봐야 한다. 지금 할 일은 자기 대표 업무 하나를 골라 완료 기준을 정하는 것이다. 그 기준을 Terra가 안정적으로 넘으면 절약하고, 재처리와 검수 부담이 커지면 Sol로 옮기자.

FAQ

Terra가 Sol보다 토큰을 적게 쓰나?

이번 비교에서 확인한 것은 동일 토큰의 단가가 절반이라는 사실이다. 같은 과제에서 실제 생성·추론 토큰이 더 적은지는 측정하지 않았으며, 사용 기록을 별도로 비교해야 한다.

Terra의 컨텍스트가 Sol보다 작은가?

공식 모델 페이지에 적힌 컨텍스트·최대 입력·최대 출력은 같다. 다만 입력 272K 초과 요청에는 장문 가격이 적용되므로, 최대 한도와 기본 단가 구간을 구분해야 한다.

Codex 구독도 정확히 두 배 오래 쓸 수 있나?

그렇게 보장할 수 없다. 크레딧의 동일 토큰 요율과 구독에 포함된 사용 한도는 구분해야 하며, 실제 업무량·추론·도구 사용에 따라 소비량이 달라진다.
